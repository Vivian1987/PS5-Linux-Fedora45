modifier le retour de steam a gnome

sudo tee /usr/bin/steamos-session-select > /dev/null << 'EOF'
#!/bin/bash
# Forcer le retour à la session GNOME AccountsService
sudo sed -i 's/^Session=.*/Session=gnome/' /var/lib/AccountsService/users/ps5
systemctl restart gdm
EOF
sudo chmod +x /usr/bin/steamos-session-select

Attention à un petit détail crucial avant de tester : dans le script /usr/bin/steamos-session-select que vous venez de créer, la ligne systemctl restart gdm n'a pas sudo devant. Comme Steam s'exécute en tant qu'utilisateur ps5 (et non root), systemctl restart gdm risque de demander un mot de passe via Polkit ou d'échouer silencieusement, ce qui vous ramènerait encore sur Steam.

Ajoutez sudo devant systemctl restart gdm avant de lancer votre test :

sudo sed -i 's|^systemctl restart gdm|sudo systemctl restart gdm|' /usr/bin/steamos-session-select

Vérification : Tapez cat /usr/bin/steamos-session-select pour confirmer que la dernière ligne affiche bien sudo systemctl restart gdm.

Ce double déclenchement (et la demande de mot de passe) vient de deux choses précises :

    AccountsService est mis en cache en mémoire par le démon accounts-daemon : quand sed modifie le fichier /var/lib/AccountsService/users/ps5 directement sur le disque, GDM lit encore l'ancienne session en mémoire au premier redémarrage, puis recharge le fichier au second. Utiliser la commande officielle D-Bus (busctl) met à jour la session en temps réel dès le premier coup.

    Il manque la règle NOPASSWD pour /usr/local/bin/switch-session (ou sed / systemctl) dans /etc/sudoers.d/ps5-session, ce qui explique pourquoi il demande le mot de passe au clic.

Appliquez ces deux corrections dans votre terminal sous GNOME pour que la bascule se fasse en un seul clic et sans mot de passe dans les deux sens :

Corriger les permissions sudoers (suppression complète du mot de passe pour la bascule)

sudo tee /etc/sudoers.d/ps5-session > /dev/null << 'EOF'
ps5 ALL=(ALL) NOPASSWD: /usr/local/bin/switch-session, /usr/bin/steamos-session-select, /usr/bin/sed, /usr/bin/systemctl restart gdm, /usr/bin/busctl
EOF
sudo chmod 440 /etc/sudoers.d/ps5-session

Vérification : Tapez sudo visudo -c ; le terminal doit afficher /etc/sudoers.d/ps5-session: parsed OK.

Mettre à jour /usr/local/bin/switch-session et /usr/bin/steamos-session-select via D-Bus (busctl)
En passant par D-Bus au lieu de modifier le fichier à la main, GDM applique immédiatement la nouvelle session sans décalage :


sudo tee /usr/local/bin/switch-session > /dev/null << 'EOF'
#!/bin/bash
USER_ID=$(id -u ps5)
CURRENT=$(busctl get-property org.freedesktop.Accounts /org/freedesktop/Accounts/User$USER_ID org.freedesktop.Accounts.User Session | awk -F'"' '{print $2}')

if [ "$CURRENT" = "gamescope-session" ]; then
    TARGET="gnome"
else
    TARGET="gamescope-session"
fi

sudo busctl call org.freedesktop.Accounts /org/freedesktop/Accounts/User$USER_ID org.freedesktop.Accounts.User SetSession s "$TARGET"
sudo systemctl restart gdm
EOF
sudo chmod +x /usr/local/bin/switch-session

sudo tee /usr/bin/steamos-session-select > /dev/null << 'EOF'
#!/bin/bash
USER_ID=$(id -u ps5)
sudo busctl call org.freedesktop.Accounts /org/freedesktop/Accounts/User$USER_ID org.freedesktop.Accounts.User SetSession s "gnome"
sudo systemctl restart gdm
EOF
sudo chmod +x /usr/bin/steamos-session-select

Vérification : Tapez sudo -n /usr/local/bin/switch-session --help 2>/dev/null; echo $? — notez que l'exécution directe redémarrera immédiatement la session, donc vérifiez plutôt la syntaxe avec bash -n /usr/local/bin/switch-session && bash -n /usr/bin/steamos-session-select && echo "OK" (doit afficher OK).
